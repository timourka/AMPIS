# Лабораторная № 2 · Многопользовательский файловый сервис

## Запуск

Из папки `Lab2`:

```sh
docker compose up --build --wait
```

Откройте [http://localhost:8088](http://localhost:8088). Если порт занят, задайте `LAB2_PORT` в `.env`. Остановить систему: `docker compose stop`. Проекты открываются в Visual Studio через `Lab2.sln`. Для сборки вне Docker нужен .NET SDK 9.

## Элементы логической схемы задания

| Код | Элемент | Технология | Назначение |
|---|---|---|---|
| G1 | Шлюз и веб-интерфейс | ASP.NET Core Minimal API, `HttpClient`, HTML/CSS/JS | Отдельные страницы операций, маршрутизация API, передача токена |
| S1 | Пользователи | ASP.NET Core Minimal API, `PasswordHasher`, JWT, Entity Framework Core / Npgsql | Регистрация, вход, смена имени |
| B1 | Пользователи | PostgreSQL 16, в контейнере `s1` | Учётные записи и outbox |
| S2 | Загрузка файлов | ASP.NET Core Minimal API, Entity Framework Core / Npgsql | Загрузка и удаление своих файлов |
| S3 | Скачивание файлов | ASP.NET Core Minimal API, Entity Framework Core / Npgsql | Выдача файла и учёт скачивания |
| B2 | Хранилище файлов | PostgreSQL 16, `bytea`, в контейнере `b2` | Оригиналы, атрибуты файлов и outbox S2 |
| B3 | БД S3, выделена из B2 | PostgreSQL 16, в контейнере `b3` | `files_read` – копия таблицы файлов; `lab` – история и outbox S3 |
| S4 | Поиск и отчёты | ASP.NET Core Minimal API, Entity Framework Core, SQL для применения событий, RabbitMQ.Client | Списки, поиск, сортировка, пагинация, статистика владельца |
| B4 | Списки и отчёты | PostgreSQL 16, в контейнере `s4` | Локальная модель чтения: пользователи, файлы и скачивания |
| D1 | Шина | RabbitMQ 4, AMQP 0-9-1, JSON, fanout | События S1/S2/S3, отдельная постоянная очередь S4 |

Браузер обращается только к G1. Nginx не используется. Контейнеры `s1` и `s4` содержат по одному экземпляру приложения и PostgreSQL. Данные остальных сервисов физически разнесены по своей паре контейнеров приложения и базы. Только G1 публикует порт наружу.

## Файлы, CQRS и события

По заданию принимаются **произвольные форматы** – нет списка разрешённых или запрещённых расширений. Лимит файла – **1 МиБ (1 048 576 байт)**. Файл хранится как непрозрачный массив байтов, не выполняется, не распаковывается и не показывается в браузере как страница. Скачивание выполняется как вложение (`application/octet-stream`, `Content-Disposition: attachment`). Это политика хранения и выдачи, а не проверка на вредоносное содержимое.

S2 пишет и удаляет в B2. PostgreSQL логически реплицирует только таблицу `files` в `b3/files_read`. S3 читает копию с ролью только для чтения и фиксирует скачивания в отдельной БД `b3/lab`. S4 обновляет свою модель чтения через RabbitMQ. Байты файлов не проходят через шину. Из-за независимой доставки события и репликации новая карточка может кратко появиться до доступности файла, а удалённый файл – кратко оставаться доступным в копии.

«Мои файлы» и «Удаление» получают файлы текущего владельца из S2 (`GET /api/my-files`). «Скачивание» показывает файлы из реплики S3 (`GET /api/downloads`), в том числе гостям. Эти списки не зависят от S4. При остановке S4 недоступны общий каталог с поиском и статистика, но скачивание и удаление работают через свои списки.

S1–S3 записывают исходящее событие в outbox в той же транзакции, что и изменение данных. Фоновый обработчик удаляет его после подтверждения брокера. S4 фиксирует идентификатор события и обновляет данные в одной транзакции, затем подтверждает доставку. Повтор не должен удваивать счётчик.

Скачивание учитывается после успешной подготовки файла к выдаче и записи истории, а не после подтверждения сохранения на устройстве. Статистика показывает число скачиваний, отдельно число гостевых скачиваний и имена зарегистрированных пользователей. Пароли и ключи в compose – только для локального учебного запуска.

## Проверка и UML

```sh
python verify.py
```

`verify.py` поднимает отдельный Compose с тестовыми БД на порту 18088, запускает `smoke.py` и `failures.py`, затем удаляет тестовые контейнеры и тома даже при ошибке. Рабочие данные не используются. Для S3 и S4 в тестах .NET задайте `LAB2_TEST_DB` со строкой подключения к одноразовому PostgreSQL.

`Lab2.vpp` – редактируемый проект Visual Paradigm с семью UML-диаграммами. Экспорт из Visual Paradigm – в `docs/vp`. В `docs/uml` – исходники PlantUML (`.puml`) и экспорты SVG. Чтобы перерисовать их, запустите PlantUML с параметрами `-charset UTF-8 -tsvg docs/uml/*.puml`.
